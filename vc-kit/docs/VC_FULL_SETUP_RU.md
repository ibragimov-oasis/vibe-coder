# VC_FULL_SETUP_RU

Полная инструкция: как корректно установить `vc-kit`, избежать конфликтов и проверить, что всё действительно активировалось.

---

## 0) Важная модель использования

`vibe-coder` — это **репозиторий-источник**.
В рабочий проект обычно переносится только папка `vc-kit/`.

Это ключевой момент, чтобы не перетирать ваш `README.md` и другие корневые файлы проекта.

---

## 1) Базовая установка (без конфликтов в корне проекта)

```bash
git clone https://github.com/ibragimov-oasis/vibe-coder.git
cp -R vibe-coder/vc-kit /path/to/your-project/
cd /path/to/your-project
bash vc-kit/install.sh --dry-run
bash vc-kit/install.sh
```

Почему сначала `--dry-run`:
- заранее показывает, какие пути будут затронуты;
- помогает выбрать стратегию для конфликтов.

---

## 2) Что делает установщик

`vc-kit/install.sh` устанавливает:

- `vc-kit/configs/vc-claude` → `.claude`
- `vc-kit/configs/vc-cursor` → `.cursor`
- `vc-kit/configs/vc-github` → `.github`
- `vc-kit/configs/vc-antigravity` → `.antigravity`
- `vc-kit/configs/vc-codex` → `.codex`
- `vc-kit/configs/vc-gemini` → `.gemini`
- `vc-kit/rules/vc-cursorrules` → `.cursorrules`
- `vc-kit/rules/vc-obsidianignore` → `.obsidianignore`
- `vc-kit/rules/vc-env-example` → `.env.example`

При конфликте:
- `merge` — копируются только отсутствующие файлы;
- `skip` — путь пропускается;
- `backup` — текущий путь бэкапится и заменяется.

Лог: `vc-kit-install-<timestamp>.log` в корне вашего проекта.

---

## 3) Почему может казаться, что «ничего не работает»

Частые причины:

1. **Конфиги не в том проекте**
   - Нужно, чтобы `.claude/.cursor/.github/...` были в корне именно того проекта, где работает агент.

2. **Не перезапущена сессия IDE/агента**
   - После установки обычно нужен reload окна/проекта или новая сессия.

3. **Другой runtime/интерфейс**
   - Разные интерфейсы (Copilot Task Agent, IDE Copilot, Codex CLI, Claude Code и т.д.) имеют разные системные ограничения и не обязаны одинаково выполнять одни и те же внутренние правила.

4. **Ожидание автоматического запуска всего пайплайна**
   - Оркестрация/безопасность/память могут требовать явного запуска инструментов и наличия зависимостей в окружении проекта.

5. **Ограничения конкретного чата/рантайма**
   - В некоторых окружениях (включая task/sandbox-режимы) агент работает по системным ограничениям платформы и не обязан автоматически запускать внешний стек (например Shannon/Lightpanda/полную оркестрацию), даже если такие инструкции лежат в `.github`/`.codex`/`.claude`.
   - Поэтому «инструкции в репо» = желаемое поведение для совместимого интерфейса, но фактическое поведение всегда зависит от возможностей текущего runtime.

---

## 4) Практическая проверка после установки

В корне вашего рабочего проекта:

```bash
ls -la .claude .cursor .github .antigravity .codex .gemini 2>/dev/null
ls -la .cursorrules .obsidianignore .env.example 2>/dev/null
```

Если папка/файл отсутствует — вернитесь к `vc-kit-install-*.log` и проверьте, что именно было `skip/merge/backup`.

---

## 5) Нужен ли rename README для избежания конфликтов

Для целевого проекта — обычно **нет**, если вы используете рекомендованный путь:
- копируете только `vc-kit/`, а не весь root `vibe-coder`;
- запускаете `vc-kit/install.sh`.

Тогда ваш существующий корневой `README.md` не затрагивается.

---

## 6) Рекомендованный рабочий поток обновлений

1. Обновить `vibe-coder`.
2. Перекопировать только `vc-kit/` в ваш проект.
3. Запустить `bash vc-kit/install.sh --dry-run`.
4. Запустить `bash vc-kit/install.sh`.
5. Перезапустить IDE/сессию агента.

---

## 7) Если хотите «максимально безопасный» режим

Используйте только:

```bash
bash vc-kit/install.sh --dry-run
bash vc-kit/install.sh --yes
```

`--yes` включает non-interactive режим с default=`merge`, то есть не перезаписывает существующие файлы целиком.
